## Source-first divergence and implementation boundary

At the recorded source base, [PacketHandler](../../Carthago/Services/PacketHandler.cs) admits selected Ethernet/raw/cooked IP, drops non-IP EtherTypes and does not provide a general attested, reassembled GDB command stream. [TrafficCaptureService](../../Carthago/Services/TrafficCaptureService.cs) supplies SharpPcap/ETW paths; ETW summaries are not complete GDB packets. [TrafficRecord](../../Carthago/Models/TrafficRecord.cs) has no trusted GDB server/process identity, RPC interface/opnum outcomes, L2 topology or OT role evidence. Existing [OT helpers](../../Carthago/Services/OtProtocolLight.cs), [CIP/MQTT](../../Carthago/Services/NetworkBatch226230Wire.cs), [CoAP/RTSP](../../Carthago/Services/NetworkBatch231235Wire.cs), [FTP/SMB2](../../Carthago/Services/NetworkBatch246250Wire.cs), [port resolver](../../Carthago/Services/PortServiceResolver.cs), [Cisco Syslog](../../Carthago/Services/Cisco/CiscoSyslogListener.cs), [active SNMP](../../Carthago/Services/Cisco/SharpSnmpClientAdapter.cs), [Windows audit](../../Carthago/Services/TrustedAudit/WinRmLocalSecurityAuditReader.cs) and prior isolated protocol inspectors do not establish these missing producers. Port names are hints, not parsers.

New [GdbRspCommandInspector](../../Carthago/Services/ProtocolIntelligence/GdbRspCommandInspector.cs) is **stateless, allocation-free, no registration, no alerts**. It requires explicit caller attestation of **one complete packet**, **plaintext**, **trusted capture provenance**, and **client-to-stub direction**. It bounds encoded packet data to 4096 bytes; requires `$...#HH` exact framing, hex checksum over encoded bytes, rejects unescaped framing delimiters and invalid/dangling escapes, and conservatively recognizes only command families by first-byte shape. Its enum/record output contains only command family, encoded length, escape presence and an **unverified** potentially-state-changing flag. No command payload, memory/register bytes, debugger arguments, user identity or IP address is retained. It does **not** validate full command grammar, negotiated packet size, retransmission, no-ack state, server acceptance, debugger authentication, actual memory writes or execution. Some valid extension packets may be rejected; a checksum-valid synthetic frame is not proof of a genuine debugger or compromise. TLS/encrypted tunnels are **NOT OBSERVABLE** without trusted endpoint/proxy evidence. Serial links require a separate input adapter.

Rollback removes only optional adapter/registration and typed extension while retaining isolated parser and historical GA. L2 EDP/POWERLINK/FDP would require a distinct safe frame-adapter integration GA.
