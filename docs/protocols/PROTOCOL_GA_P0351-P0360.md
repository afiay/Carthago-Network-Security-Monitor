| **P0351 `pipe` — SMB Pipe Protocol** | **REJECTED_DUPLICATE_OR_NOT_A_PROTOCOL** (separately counted) | [Microsoft named pipes](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-wpo/4de75e21-36fd-440a-859b-75accc74487c) and [RPC over SMB](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rpce/7063c7bd-b48b-42e7-9154-3c2ec4113c0d) describe a transport endpoint carried by SMB/SMB2, not an additional independent on-wire protocol. | **P0352 `pkixac` — PKIX Attribute Certificate** | **REJECTED_DUPLICATE_OR_NOT_A_PROTOCOL** | [RFC 5755](https://www.rfc-editor.org/info/rfc5755/) (which obsoletes RFC 3281) specifies an X.509 **authorization certificate profile**, not a distinct host-to-host transport protocol. Certificate contents may be in protected application data and can contain sensitive attributes; a TLS port/handshake does not expose them. No independent packet decoder. |

Normal subscriber discovery/reconnect is benign. Do not misclassify UDP ports as PPPoE. |

It could be useful as a separate Linux host sensor with trusted namespace, interface, sampling rate, origin and lost-sample counters. Sampling is normal network operations; missing samples are not proof of evasion. Current Windows capture backend has no Linux Netlink producer. Do not invent cross-host parser coverage. |

Abuse of referrals requires trusted Exchange/DC endpoint role, authenticated RPC interface/opnum, server referral target and success/denial logs; normal address-book redirects are benign. No attested RPC PDU stream, Exchange logs or applicable deployed-version inventory at this HEAD. Defer standalone inspector rather than infer a referral from TCP/135. |
