## Source-first divergence and implementation boundaries

Inspected current [PacketHandler](../../Carthago/Services/PacketHandler.cs), [TrafficCaptureService](../../Carthago/Services/TrafficCaptureService.cs), [TrafficRecord](../../Carthago/Models/TrafficRecord.cs), [OtProtocolLight](../../Carthago/Services/OtProtocolLight.cs), [NetworkBatch226230Wire](../../Carthago/Services/NetworkBatch226230Wire.cs), [NetworkBatch231235Wire](../../Carthago/Services/NetworkBatch231235Wire.cs), [NetworkBatch246250Wire](../../Carthago/Services/NetworkBatch246250Wire.cs), [PortServiceResolver](../../Carthago/Services/PortServiceResolver.cs), ETW/Windows Security and Cisco SNMP/Syslog adapters, prior protocol-owned inspectors/tests, [engineering standard](../rules/RULE_DOCUMENTATION_STANDARD.md), detection/UI ledgers **read-only**, and the .NET 8 SDK-style [main](../../Carthago/Carthago.csproj) and [xUnit](../../Carthago.Tests/Carthago.Tests.csproj) project definitions. SDK-style projects automatically compile new C# files in owned folders. No dependencies added.

The existing Ethernet fast path drops non-IP frames; the IP fast path handles TCP/UDP/ICMP, not every IP protocol. The UDP parser extracts payload bytes, but does **not** attest every fragmentation, capture completeness or trusted source property needed for registration. TCP early inspection is not general reassembly. Existing DNS request/response parsing is not authenticated DNS-server evidence. No shared producer, `TrafficRecord` schema, journal, detection rule, UI resource or security policy was changed.

**TFTP strict source-only profile:** exactly one initial RFC 1350 RRQ (opcode 1) or WRQ (opcode 2), leading zero opcode byte, destination UDP/69, non-69 source port, explicit `verifiedCompleteUdpPayload=true`, payload length 10–1024 bytes. Require one nonempty printable ASCII filename of at most 255 bytes and a nonempty ASCII transfer mode (`octet`, `netascii`, `mail`, case-insensitive) of at most 16 bytes. RFC 2347 option extensions, if present, must be complete nonempty NUL-terminated name/value pairs, at most eight pairs; names at most 32 bytes, values at most 64, printable ASCII without spaces, case-insensitive duplicate option names rejected. Option *semantics*, block-size validity, path access and credentials are not verified. These are conservative parser limits, not claims that all RFC-valid deployments fit them. All request strings remain in the caller-owned input span and are never returned, stored or logged.

**Unsupported by design:** DATA/ACK/ERROR/OACK, dynamic transfer IDs, retransmission/session matching, file contents, transfer completion, encryption, authenticity, endpoint trust, path-based exfiltration detection, CVE exploitation and real asset changes. The stateless inspector performs bounded stack-only parsing, no heap allocation for input strings, no regex, no state, I/O, alerts, journal writes, UI or sinks. **ISOLATED — NOT LIVE-CAPTURE INTEGRATED**.
