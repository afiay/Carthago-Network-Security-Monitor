Existing parser helpers are limited wire-shape recognizers. The fast path drops non-IP EtherTypes and does not register this RGMP inspector; no live evidence producer for RGMP group state exists. The SDK-style [application](../../Carthago/Carthago.csproj) and [test project](../../Carthago.Tests/Carthago.Tests.csproj) automatically include the isolated new `.cs` files; neither project was edited.

**P0289 threat hypothesis:** forged RGMP Hello/Leave could cause multicast blackholing; forged Join could attract unwanted multicast traffic (RFC 3488 §6). Typed fields now available **only from caller-attested synthetic/plaintext payload**: untrusted RGMP message kind, group-specific flag, forbidden-group flag, reserved-byte flag. Source IP, multicast group address, switch port and packet contents are intentionally **not retained**. A real rule would additionally require trusted Ethernet interface/switch port, IPv4 source, router inventory, group membership baseline and switch multicast forwarding/audit outcomes. Periodic legitimate Hello/Join/Leave/Bye are expected false positives; a syntactically valid packet never proves spoofing, forwarding change, CVE exploitation or alert confidence.

**Parser bounds:** exact 8-byte payload; protocol 2; IPv4 destination 224.0.0.25; TTL 1; RFC checksum; four allowed types; Hello/Bye zero group; Join/Leave multicast group. Nonzero reserved byte is accepted as RFC reception semantics require. Disallowed sender groups 224.0.0/24 and 224.0.1.39/.40 are flagged without fabricating an authenticated outcome. Stateless, no allocations proportional to input, no persistent memory, no network I/O, no credentials, no direct alerts or journal writes. Caller attestation is a required input contract, **not proof of a trusted live producer**.
