## Source-first divergence and implementation boundaries

- Live [PacketHandler](../../Carthago/Services/PacketHandler.cs) rejects non-IP EtherTypes and unsupported link types; Ethernet/IP, raw IP, loopback and Linux cooked paths do not constitute 802.11/802.15.4 radio capture. [TrafficCaptureService](../../Carthago/Services/TrafficCaptureService.cs) feeds the existing record pipeline, not a ZEP-aware typed producer. [TrafficRecord](../../Carthago/Models/TrafficRecord.cs) has no authenticated ZEP sensor/PHY observation contract.
- Existing [OT classifiers](../../Carthago/Services/OtProtocolLight.cs), [CIP/MQTT helpers](../../Carthago/Services/NetworkBatch226230Wire.cs), [CoAP/RTSP helpers](../../Carthago/Services/NetworkBatch231235Wire.cs), [FTP/SMB2 helpers](../../Carthago/Services/NetworkBatch246250Wire.cs), [port resolver](../../Carthago/Services/PortServiceResolver.cs), Windows audit/ETW and Cisco Syslog/SNMP integrations do not establish native Wi-Fi, 802.15.4 or ZEP framing. An IANA port label is not a decoder.
- `Carthago.csproj` and `Carthago.Tests.csproj` use SDK-style default C# compilation; isolated files under the existing `ProtocolIntelligence` folders require no project edit or new dependency. New API is standalone and does not modify public existing contracts.
- The inspector uses `ReadOnlySpan<byte>`, strict exact-length validation, maximum 159-byte UDP payload, big-endian sequence, no allocations or shared state, no regex, no mutable caches, no decoding of radio bytes and no raw data retention. Version 1, version 3, unknown types, unsupported channels/modes, fragmented/truncated or length-mismatched envelopes fail closed as **unsupported**, not malicious.
- No new RNNN rule, detection event, alert, UI action, telemetry schema, outbox, journal change, or shared-core edit. Existing JSONL journal-first and immutable raw DetectionEvent contracts, holdouts, privacy, confidence floors, cooldowns, modes and suppression remain untouched.
