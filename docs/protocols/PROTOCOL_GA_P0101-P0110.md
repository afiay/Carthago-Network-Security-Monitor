## Strict parser boundaries and privacy

**LPD:** exact initial command line, client-to-server TCP/515, 3–256 total bytes, final LF, command byte 1–5. Conservative ASCII queue token 1–64 bytes (letters, digits, dot, dash, underscore); at most eight space-separated printable ASCII arguments, each 1–32 bytes, for query/remove commands. Remove-jobs requires an agent token. Reject empty/repeated/trailing spaces, CR, embedded LF, malformed queue tokens, unexpected arguments on commands 1/2, overlong input and missing caller completeness attestation. This conservative subset can reject legitimate nonstandard queues/arguments; it is not a full RFC 1179 parser. **Never return** queue name, agent, job IDs or raw command. No job subcommand, ACK, authentication, user authority, print content or completion is inspected.

**RFB:** exactly 12 bytes `RFB 003.00[3|7|8]\\n` with actual LF (ASCII 0x0A), explicit caller-attested direction and complete greeting, and server port 5900–5999. This deliberately excludes custom ports and unrecognized version extensions. It does not parse security-type negotiation, passwords, challenge-response, screen data, clipboard, extensions or encrypted tunnels. Return only version numbers and direction. No session state, network I/O, alerts, logs, UI or sink effects. Neither parser can prove exploitation, identity, authorized/unauthorized action, success, or asset change. **ISOLATED — NOT LIVE-CAPTURE INTEGRATED.**
