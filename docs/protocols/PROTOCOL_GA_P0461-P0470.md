## Source-first divergence and precise implementation contract

- Live [PacketHandler](../../Carthago/Services/PacketHandler.cs) supports Ethernet/IP, raw IP, loopback and Linux cooked paths but drops non-IP EtherTypes, with bounded early TCP inspection rather than general stream reassembly. [TrafficCaptureService](../../Carthago/Services/TrafficCaptureService.cs) and [TrafficRecord](../../Carthago/Models/TrafficRecord.cs) provide no authenticated ERSPAN session or mirror-switch provenance. No new input adapter exists in the inspected source path.
- Existing [GRE inspector](../../Carthago/Services/ProtocolIntelligence/GrePacketInspector.cs) handles RFC 2784/2890 IPv4, IPv6 and transparent Ethernet inner types, not 0x88BE/0x22EB ERSPAN. Reuse the architectural pattern, not its accepted-type assumptions. Existing OT, CIP/MQTT, CoAP/RTSP, FTP/SMB, IANA port resolver, Windows audit/ETW and Cisco SNMP/Syslog do not establish the missing serial, link-layer, TrustSec or authenticated mirror sources.
- The SDK-style `Carthago.csproj` and `Carthago.Tests.csproj` use default C# compilation; isolated `ProtocolIntelligence` files require no project or dependency changes. New [source](../../Carthago/Services/ProtocolIntelligence/ErspanTypeIIEnvelopeInspector.cs) has a stateless `ReadOnlySpan<byte>` interface, exact fixed GRE/feature header offsets, network-order reads, a 16,384-byte input cap and strict four-part caller attestations. It never stores mirrored bytes, MAC addresses, sensitive fields or keys, never allocates per packet, never emits events, alerts, UI messages or external sinks.
- Protocol classification is **not** proof of authorized configuration, attack, CVE exploitation, complete mirrored data or delivery. Type II may be carried over IPv4 or IPv6 if an upstream trusted producer supplies the exact full GRE payload. The inspector does not itself handle IP fragments, GRE checksum/key variants, Type III optional headers, inner FCS or authentication. Failures return `false` and reset the output.
- No shared-core changes: `PacketHandler.cs`, `TrafficRecord.cs`, capture service, project files, rule registry, RNNN definitions, detection/UI ledgers, journal, outbox, holdouts, privacy, confidence floors, modes, cooldowns and suppression remain untouched.

## Threat refresh, original sources and observability

- **ERSPAN format:** [Cisco-authored IETF individual Internet-Draft, August 2017, section 4.2](https://datatracker.ietf.org/doc/html/draft-foschiano-erspan-02) defines GRE 0x88BE with S bit, 8-byte Type II header and VLAN, CoS, truncation, session and index. This is an expired Internet-Draft, not an RFC or exploit advisory; source-only inspector uses the published wire layout without copying third-party code. [RFC 2784](https://www.rfc-editor.org/rfc/rfc2784) and [RFC 2890](https://www.rfc-editor.org/rfc/rfc2890) specify GRE framing and sequence extension.
- **Cisco Auto-RP:** [Cisco Secure IP Multicast Deployments, 2022-08-24](https://www.cisco.com/c/en/us/support/docs/ip/ip-multicast/218004-secure-ip-multicast-deployments.html) documents IPv4 UDP/496 and multicast groups 224.0.1.39/40, and control-plane filtering concerns. This is architecture guidance, **not** evidence of active exploitation.
- **Microsoft ATSvc:** [MS-TSCH overview](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-tsch/21e8e86e-ee5a-469d-917f-28a41f3c25a4) and [transport](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-tsch/400d77fe-2f1a-4a8e-a90b-a8f82fad5a20) define RPC interfaces and security prerequisites; no remotely created task or compromise is inferable from a packet header.
- **2026-11-01 refresh:** [CISA KEV catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) and [official JSON feed](https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json) were checked; JSON retrieval returned HTTP 403, so complete current KEV membership is **not verified**. [FIRST EPSS](https://www.first.org/epss/data) publishes CVE-specific daily probabilities, but no candidate-specific confirmed CVE or score was established; **no EPSS estimate claimed**. No dated vendor advisory establishing exploitation of these ten protocol surfaces was found in the checked official sources. **All ten: UNVERIFIED for candidate-specific exploitation**; no CVE, affected version, prerequisite, IOC or zero-day signature is invented.
