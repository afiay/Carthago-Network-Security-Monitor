## Actual source, reachability and safety

At source base SHA, [PacketHandler](../../Carthago/Services/PacketHandler.cs) admits selected Ethernet/raw/cooked IP link types, drops non-IP EtherTypes and fragmented IPv4, and does not provide a general trusted TCP stream-reassembly/complete IPFIX message boundary. [TrafficCaptureService](../../Carthago/Services/TrafficCaptureService.cs) handles SharpPcap/ETW; ETW traffic summaries are not complete IPFIX payloads. [TrafficRecord](../../Carthago/Models/TrafficRecord.cs) lacks authenticated collector/exporter and IPFIX template/observation-domain outcomes. Existing [OT helpers](../../Carthago/Services/OtProtocolLight.cs), [MQTT/CIP](../../Carthago/Services/NetworkBatch226230Wire.cs), [CoAP/RTSP](../../Carthago/Services/NetworkBatch231235Wire.cs), [FTP/SMB2](../../Carthago/Services/NetworkBatch246250Wire.cs), [IANA resolver](../../Carthago/Services/PortServiceResolver.cs), [Cisco Syslog](../../Carthago/Services/Cisco/CiscoSyslogListener.cs), [active SNMP](../../Carthago/Services/Cisco/SharpSnmpClientAdapter.cs), [Windows Security](../../Carthago/Services/TrustedAudit/WinRmLocalSecurityAuditReader.cs), and existing isolated protocol inspectors were reviewed for overlapping producers. Port names and software dependencies do not constitute a passive IPFIX decoder.

New [IpfixMessageInspector](../../Carthago/Services/ProtocolIntelligence/IpfixMessageInspector.cs) is a **stateless, allocation-free, bounded IPFIX v10 envelope classifier**, NOT a collector, template decoder, authenticated exporter, NetFlow v9 parser or live detection. It requires caller-attested exact one-message boundary, plaintext and sensor provenance; checks version 10, 16–65535 byte declared length, Set IDs and bounded Set length walk, at most 4096 Sets; outputs only untrusted export time, sequence, observation-domain ID and Set counts. It intentionally does not validate template contents, data records, enterprise fields, retransmission, exporter trust or actual flow/security outcomes. Valid IPFIX with more than 4096 very small Sets is conservatively rejected. Malformed and unsupported versions fail closed; nonzero Data Set payload is opaque, not an exploit signal. No raw addresses, payload, credentials or PII retained. No journal/alerts/UI/telemetry contract changes.

**Integration proposal, not authorized or applied:** separately approve a narrow, trusted IPFIX collector/message-boundary adapter that supplies complete UDP or reassembled TCP/SCTP messages with source and transport identity, bounded per-exporter/template session state and privacy-safe audit metadata. A shared [PacketHandler](../../Carthago/Services/PacketHandler.cs) / [TrafficCaptureService](../../Carthago/Services/TrafficCaptureService.cs) hook and [TrafficRecord](../../Carthago/Models/TrafficRecord.cs) schema changes are coordination-required. Compatibility checks must cover source attribution, encrypted inputs, message coalescing/fragmentation, template withdrawal/reorder, false-positive benign exporter restarts, journal-first immutable DetectionEvents, Shadow/Disabled, cooldowns and rollbacks. Rollback is removing only the optional adapter registration and retaining the isolated inspector; do not alter existing RNNN rules or the frozen R102 V1 holdout.
