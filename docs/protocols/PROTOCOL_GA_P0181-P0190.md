## Exact isolated inspector contract and false-positive boundary

DMTF DSP0136 (2003-04-23), §§3.2.1–3.2.2, specifies RMCP v1 `06 00 seq class`, class 6 for ASF, class 7 for IPMI, class high-bit for ACK, UDP 623 for compatibility and 644 for security extensions. This **strict subset** accepts only UDP/623, 4-byte ASF ACKs with non-FF sequence, or ASF non-ACK envelopes of **12–267 bytes** with exact IANA 4542, reserved fields zero, exact 8-bit declared payload length, and selected standard types `10–13`, `40–42`, `80–82`. It deliberately excludes OEM classes, IPMI class 7, RAKP, RMCP+ and secure extension port 644. A header-positive is only *syntactic recognition*, not per-message semantic validation, message integrity, request/response correlation, authenticated management or successful power operation. Nonstandard but legitimate implementations may be rejected. A spoofed structurally valid header is possible; the caller must attest complete UDP framing and independently verify the management endpoint. This parser cannot create such attestations.

The inspector is allocation-free/stateless, bounded by 267 input bytes, has no network I/O, timers, caches or shared mutable state, and returns only non-sensitive metadata. It discards sequence, tag, enterprise payload, command parameters, credentials, device identities and session identifiers. Failed classification returns default observation. **ISOLATED — NOT LIVE-CAPTURE INTEGRATED.**
