## Source-first divergence, scope and privacy

At the exact base, reviewed [canonical GA conduct](../rules/RULE_DOCUMENTATION_STANDARD.md), [architecture safety](../../Carthago/docs/ArchitectureSafetyRules.md), [rule authoring](../../Carthago/docs/AddingDetectionRules.md), [precision migration](../../Carthago/docs/RuleOwnedPrecisionDetectorMigration.md), [detection model](../../Carthago/docs/DetectionEngineeringModel.md), [detection ledger](../RULE_HARDENING_PROGRESS.md), [UI ledger](../design/CARTHAGO_UI_IMPLEMENTATION_LEDGER.md) and prior protocol GA. Also inspected [PacketHandler](../../Carthago/Services/PacketHandler.cs), [TrafficCaptureService](../../Carthago/Services/TrafficCaptureService.cs), [TrafficRecord](../../Carthago/Models/TrafficRecord.cs), [OT helpers](../../Carthago/Services/OtProtocolLight.cs), [wire 226–230](../../Carthago/Services/NetworkBatch226230Wire.cs), [231–235](../../Carthago/Services/NetworkBatch231235Wire.cs), [246–250](../../Carthago/Services/NetworkBatch246250Wire.cs), [port resolver](../../Carthago/Services/PortServiceResolver.cs), [Cisco Syslog](../../Carthago/Services/Cisco/CiscoSyslogListener.cs), [SNMP client](../../Carthago/Services/Cisco/SharpSnmpClientAdapter.cs), [Windows audit](../../Carthago/Services/TrustedAudit/WinRmLocalSecurityAuditReader.cs) and [ETW](../../Carthago/Capture/EtwCapture.cs). Neither selected protocol had an equivalent existing protocol-owned envelope inspector at the audited source scope.

[Application project](../../Carthago/Carthago.csproj) and [xUnit project](../../Carthago.Tests/Carthago.Tests.csproj) use SDK-style automatic compilation, so no project-file or dependency changes. The existing capture fast path accepts IP TCP/UDP/ICMP, drops non-IP AoE, does not guarantee full TCP reassembly, and does not attest endpoint identity. A port-service label is not a decoder. Existing ETW and Cisco adapters do not supply attested AJP/ADB message boundaries or successful actions. These new inspectors have no consumer, no alert/UI/external sink and no journal side effect.

**AJP bounded contract:** 5–8192 bytes, exact big-endian payload length, valid direction magic `0x1234` proxy→container or `0x4142` container→proxy, and only documented prefix codes with conservative minimum/exact payload sizes. Request-body frames have no prefix and are intentionally **not classified**. No AJP string, URL, header, attribute, credential, secret or body parsing; no validation of full ForwardRequest semantics. A configured larger AJP packet is deferred rather than universally malformed.

**ADB bounded contract:** 24-byte little-endian six-word header and at most 4096 payload bytes, exact declared message length, complement magic, supported classic `CNXN/AUTH/OPEN/OKAY/CLSE/WRTE` commands and conservative argument/payload shapes. Modern extensions and negotiated payloads >4096 are unsupported, not intrinsically malicious. Payload checksum, auth signature, session ordering and endpoint identity are **not verified by the inspector**. No serial number, banner, destination, command, authentication bytes, checksum, stream IDs or payload retained. The ADB host smart-socket is explicitly separate.

Both inspectors use bounded `ReadOnlySpan<byte>` and deterministic, stateless validation with no allocation on successful parse beyond value-type results. Caller attestation booleans are **preconditions, not cryptographic trust**. Spoofed headers or endpoint metadata can still cause false classifications. No encrypted contents are inspected.
