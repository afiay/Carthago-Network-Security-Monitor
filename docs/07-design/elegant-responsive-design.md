# Carthago elegant responsive UI pass

This pass turns Carthago into a calmer, more serious anomaly-first security workspace while preserving all existing monitoring, analytics, integrations, and forensic capabilities.

## Design goals

- Make the application feel like a real analyst console rather than a raw telemetry dump.
- Keep the default dashboard minimal and user-configurable.
- Improve readability for long host names, IPv6 addresses, rule IDs, and ML evidence.
- Reuse shared theme resources instead of scattering colors across views.
- Use responsive WPF layout primitives: Grid, WrapPanel, ScrollViewer, MinWidth, and reusable card styles.
- Let command bars wrap instead of clipping important buttons.
- Keep raw traffic, raw detections, Cisco tooling, sink delivery, and integrations available as advanced views.

## Areas updated

- Global theme and shared resources.
- Main shell and command header.
- Sidebar navigation grouping.
- Minimal dashboard command bar and cards.
- Anomaly timeline and signal details workspace.
- Incident queue and investigation workspace.
- External delivery view polish.
- Integrations page surface polish.

## Implementation notes

The pass is intentionally XAML-first and low risk. It does not change the analytics pipeline, capture pipeline, detection logic, incident correlation, demo mode, or persistence model. The redesign is applied through shared styles and safer layout containers.

## Responsiveness rules

- Main dashboard controls wrap using `WrapPanel`.
- Details and list panes use proportional grid columns with minimum widths.
- Long technical values use wrapping instead of truncating when important.
- Main content scrolls vertically and avoids horizontal scrolling where practical.
- Sidebar stays compact and grouped so advanced views remain accessible without cluttering the main workspace.


## v6 implementation pass — page-level SOC workspaces

This pass moves the UI closer to the attached Carthago design references while keeping the existing local-first analytics pipeline intact.

### Shell and navigation

The left shell now exposes the Security View pages as separate concepts:

- Dashboard
- Incidents
- Anomalies
- Incident Queue
- Threat Feed

Raw Traffic, Raw Detections, Sink Delivery, PCAP/forensics, analytics, integrations, host integrity, Cisco tooling, and settings remain available from the sidebar. The main dashboard remains anomaly-first and widget-driven; raw evidence stays secondary unless the operator opens an advanced view.

### Incidents / Incident Queue

`IncidentsPage` now supports both the general incident workspace and the incident queue entry point. It is still backed by the existing `AnalyticsHost.GetRecentIncidents(...)` data path. The page projects real `Incident` objects into presentation fields for:

- KPI counts
- queue rows
- selected incident details
- risk score display
- evidence / reasons
- tags and rule IDs
- MITRE-style technique hints
- affected hosts
- response checklist

The queue UI is data-bound. Demo incidents only appear when generated by the existing demo scenario.

### Anomalies

`AnomaliesPage` keeps the grouped anomaly model and adds anomaly-focused KPI cards:

- new anomalies in the last 15 minutes
- high severity signals
- ML-assisted signals
- threat-feed/reputation evidence
- baseline confidence

The timeline and details remain backed by `AnalyticsHost.GetRecentAnomalies(...)`, grouped by stable signal identity to avoid hundreds of repeated ML windows dominating the workspace.

### Threat Feed

A new `ThreatFeedPage` projects real detection events into threat-intelligence matches when detection text, severity, enrichment, or indicator data suggests IOC/reputation relevance. It does not invent a live feed. If the application has no feed-related evidence, it shows a clean empty state.

The page displays:

- feed-match KPIs
- matched IOC list
- selected IOC details
- confidence/risk score
- source, type, classification, related host, and related incident
- evidence observations
- tags and rule IDs
- top feed source and IOC-type summaries
- raw/advanced shortcuts

Blocking from the feed is intentionally disabled unless a real blocking/suppression policy is configured.

### Libraries

No new UI library was forced in this pass. The design remains native WPF/XAML and uses the existing project dependencies. Future candidates remain:

- CommunityToolkit.Mvvm for a deeper MVVM migration.
- LiveCharts2 WPF for richer gauges/sparklines.
- GongSolutions.WPF.DragDrop for stronger drag/drop behavior.

They should be added only after a clean package compatibility check because this project already carries package compatibility warnings around legacy WPF-related dependencies.
