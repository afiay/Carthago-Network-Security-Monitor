## MPTCP inspector boundary and authored scenarios

[Source](../../../Carthago/Services/ProtocolIntelligence/MptcpCapableSynInspector.cs) requires **four explicit caller attestations**: complete TCP header/options slice, initial SYN without ACK, unfragmented IP packet, and source attribution. These are caller claims, not verified by the inspector; the API has no capture registration. It accepts only complete TCP option arrays of 4–40 bytes, aligned to 4 bytes; safely walks EOL/NOP and bounded other options, rejects malformed option lengths, nonzero post-EOL padding, duplicate MPTCP options, v0/other subtypes, invalid v1 flags and missing HMAC-SHA256 negotiation. Only **RFC 8684 MP_CAPABLE v1 initial-SYN shape** (kind 30, length 4, subtype 0, version 1) is recognized. Other legitimate MPTCP messages, SYN/ACK, v0 and future extension flags are intentionally outside scope. No key/token, address, port, payload, session outcome or authentication is exposed. Strict flags/padding may reject valid future extensions. A spoofed SYN with valid option bytes is still a false-positive possibility for any security conclusion.

The inspector is stateless, bounded by TCP's 40-byte options limit, allocation-free on the inspection path, deterministic under duplicates/reordering/concurrency, and has no network, alert, journal, UI, sink, configuration, rule or holdout side effects. It does not decrypt application payload or infer hidden TLS/QUIC contents.

[Authored xUnit source](../../../Carthago.Tests/ProtocolIntelligence/MptcpCapableSynInspectorTests.cs): **19 [Fact] methods / 19 concrete xUnit invocations** (some methods contain multiple input assertions). Independent scenario groups: valid v1 positive/flag combinations and TCP option coexistence; ordinary TCP and cross-version negatives; malformed/truncated/overlong, EOL smuggling, reserved flags and duplicate options; stateless duplicate/reordering and concurrent calls; mandatory provenance attestations, privacy and fail-closed default. Synthetic RFC-derived fixtures only; no third-party capture replay. **Tests authored: 19; executed: 0. Builds: 0. CI/Actions: 0. Windows runner: 0. Replays/holdouts: 0. Live captures/scans: 0.**
