## Source-first divergence and contract boundaries

- Fresh live HEAD reviewed: [PacketHandler](../../../Carthago/Services/PacketHandler.cs), [TrafficCaptureService](../../../Carthago/Services/TrafficCaptureService.cs), [TrafficRecord](../../../Carthago/Models/TrafficRecord.cs), [OT](../../../Carthago/Services/OtProtocolLight.cs), [MQTT/CIP](../../../Carthago/Services/NetworkBatch226230Wire.cs), [CoAP/RTSP](../../../Carthago/Services/NetworkBatch231235Wire.cs), [FTP/SMB2](../../../Carthago/Services/NetworkBatch246250Wire.cs), [port hints](../../../Carthago/Services/PortServiceResolver.cs), ETW/Windows Security and Cisco SNMP/Syslog adapters. The IP-only Ethernet fast path cannot provide ISL. Existing port/service guesses, DCE/RPC header recognition and ETW source metadata are **not** decoded spooler/rexec/LSD operations.
- The SDK-style `Carthago.csproj` and `Carthago.Tests.csproj` use default compilation for new `ProtocolIntelligence` C# paths. No project or dependency edits, no parser registration, no telemetry/schema changes.
- **Rexec:** complete, ordered four-field request required; maximum 2,048 bytes; stderr-port decimal 0–65535, username 1–128 visible ASCII bytes, password at most 256 bytes (may be empty), command 1–1,024 ASCII/tab bytes. No TCP reassembly, credential storage, command parsing, remote authentication or server outcome. Segmented, encrypted or unsupported binary requests fail closed.
- **LSD:** complete attested UDP/6771 multicast datagram, maximum 1,400 bytes, 32 header lines, 256 bytes per line, up to 16 40-character hex infohash headers; mandatory Host/Port/Infohash and strict HTTP-like line termination. Unknown bounded visible-ASCII headers allowed. A caller must attest matching multicast destination; this isolated inspector cannot verify it independently. No torrent metadata or cookie retention. Other BitTorrent protocols and IPv6 transport correctness are not inferred from these bytes.
- Stateless inspectors: bounded loops, `ReadOnlySpan<byte>`, no regex, no external I/O, no network access, no new dependencies, no logging or alerts. No journal, `DetectionEvent`, rules, UI, capture core or security controls changed. An observation is **untrusted syntactic metadata**, not an authenticated asset or action.
- False positives: a crafted rexec-shaped prefix on an attested legacy endpoint or a spoofed BEP14 multicast announcement can match. Capture provenance and host/server outcome evidence must be separate. Missing attestations reject. Neither match alone supports an incident, CVE attribution or policy violation.
