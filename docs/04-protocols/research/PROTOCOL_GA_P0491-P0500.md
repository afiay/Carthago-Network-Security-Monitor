- **Changed paths (protocol-owned only):** `Carthago/Services/ProtocolIntelligence/RshRequestInspector.cs`, `Carthago.Tests/ProtocolIntelligence/RshRequestInspectorTests.cs`, this GA page, and `docs/protocols/PROTOCOL_EXPANSION_PROGRESS.md`. - **Bounds and semantics:** Stateless `ReadOnlySpan<byte>` parsing; maximum 2,048 input bytes, 256 per username, 1,024 command bytes, 5 stderr-port digits, four exact NUL-terminated fields, no trailing bytes, visible ASCII-only user identifiers and bounded printable command bytes. Nonzero secondary port must be 512–1023; privileged client source 512–1023; server destination 514. The 256-byte user bound follows Oracle's documented implementation and is deliberately wider than OpenBSD's 16-byte limit. No raw usernames, command, payload, address or secrets are retained in result. Source-port trust and server binding **must** be independently attested, never inferred from port alone.
- **Encryption and provenance:** A TCP segment is not a complete application request. The current [PacketHandler](../../../Carthago/Services/PacketHandler.cs) early TCP inspection is not an attested complete stream-start request producer. Packet source, direction, boundaries and plaintext are caller preconditions, not facts the isolated inspector can establish. No SSH/TLS/QUIC payload decoding. No authentication, remote execution, CVE exploit or privilege outcome inferred.
- **False positives and false negatives:** Authorized legacy rsh automation looks identical to misuse; service/port masquerading and similar NUL-field protocols can resemble rsh if producer attestation is wrong. Reordered, truncated, binary, non-ASCII, oversized, unusual-port or implementation-specific valid variants fail closed. No mutable state, timers, background work, network I/O, regex, allocation proportional to attacker-controlled lengths, logging or direct alerts.
- **Shared integration proposal, NOT applied:** after explicit owner approval and cross-stream review, add a narrow optional read-only TCP stream-boundary adapter upstream of `PacketHandler`/telemetry, exposing verified source/destination ports, client direction, complete request boundary, plaintext status, service binding and capture provenance. Call this inspector only on a bounded, reassembled, complete request; emit a **separate versioned, privacy-redacted candidate observation**, not a synthetic DetectionEvent, and preserve JSONL journal-first raw event truth.
