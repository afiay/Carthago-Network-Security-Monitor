## New isolated parser: boundaries and source-only test evidence

[HicpConfigurationAttemptInspector](../../../Carthago/Services/ProtocolIntelligence/HicpConfigurationAttemptInspector.cs) is a stateless, allocation-free request-shape observer with a **1200-byte datagram cap**, **128-byte field cap**, **24-field cap**, exact legacy `Configure: ` and target MAC delimiter checks, ASCII-printable bounded key/value parsing, and no password/MAC/IP/hostname retention. It rejects unknown-only fields, malformed hex target, invalid separators, embedded second Configure frame, NUL/control characters, overlong and unsupported messages; all six attestations (complete UDP, unfragmented IP, UDP/3250, plaintext, provenance and direction) must be true. The inspector does **not** authenticate HICP, validate configuration semantics, decode SHICP, distinguish authorized commissioning from misuse, or prove a server accepted changes. Legitimate device provisioning and crafted lookalike plaintext can produce the same request shape.

[Authored isolated xUnit scenarios](../../../Carthago.Tests/ProtocolIntelligence/HicpConfigurationAttemptInspectorTests.cs): **20 methods / 28 concrete invocations** (two theories with four and six rows; eighteen facts). Independent cases cover valid IP/subnet/gateway/DHCP and multi-field requests, privacy-safe password-change presence, Module scan/SHICP/HTTP negatives, prefix/target/delimiter/field spoofing, NUL/CRLF/truncation/coalescing, overlong datagram/field/count, all six missing provenance gates, stateless duplicate/reordering, concurrent calls, no retained credentials, and fail-closed default outputs. All fixtures are **synthetic and non-secret**; no captured real-device differential validation. **0 executed; 0 builds; 0 replay/holdout/CI/runner/live capture/active scan.**
