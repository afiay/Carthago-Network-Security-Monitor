## P0423 inspector and false-positive boundaries

Accepts at most 4,096 bytes; requires at least 37 bytes, three exact four-byte ASCII tags, exactly eight ASCII hex digits per token, protocol version 1 or 2, 1–128 declared arguments and 1–256 first-argument bytes present. Reads a bounded first prefix only, with no allocation from untrusted lengths, no network state, no string parsing of untrusted content, no retained command/source data, no direct alerts or sinks. Rejects incomplete/misordered/overlong prefixes and missing attestation. These conservative limits can reject legitimate long first arguments or segmented initial TCP payloads; they are explicitly false negatives, not evidence of malice. Valid prefix is only syntactic shape; spoofed traffic can imitate it. No v3 CDIR path, SSH decryption, job completion, process execution, exploit success, identity or authorization proof.

**Integration proposal — NOT APPROVED OR APPLIED:** a separate coordination GA would introduce a bounded TCP connection-start/reassembly producer, verified distcc endpoint and direction, capture provenance and an optional typed `DistccRequestPrefixObservation` consumer without changing existing `TrafficRecord` contracts. Author compatibility tests for TCP split/overlap/retransmission, encrypted SSH, unknown port, benign builds, role/asset mapping, event journal integrity, and rollback by disabling only the optional adapter. Owner approval and live cross-stream review required before any shared wiring.
